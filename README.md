# StudyTrace v0.1

講師の方針 → Sprint → Today → 実際の学習記録 → 指導用レポートをつなぐ、個人用・Local Firstの学習管理アプリです。React / TypeScript / Vite / Dexie / Zustand / Zod / Rechartsを使用し、認証・外部API・バックエンドはありません。

## 起動

### GitHub Pages / スマートフォン

公開URL: https://NeuralEquation.github.io/studytrace/

「インストール済み」と表示されて追加できない場合は、[インストール専用ページ](https://neuralequation.github.io/studytrace/install.html)をChromeなどの通常タブで開いてください。古い画面が出る場合や更新待ちの場合は、学習を保存してすべてのStudyTraceのタブ・アプリを閉じ、このページを開き直します。サイトデータや学習記録を消す必要はありません。解消しない場合は、専用ページの確認情報をコピーできます。

- Android: Chromeで開き、メニューの「ホーム画面に追加」または「アプリをインストール」。
- iPhone / iPad: Safariで開き、共有メニューから「ホーム画面に追加」。
- 初回はオンラインで開いて読み込みを完了してください。その後はアプリ本体と学習記録をオフラインで利用できます。
- 旧HTML版やlocalhostとは保存領域が異なります。旧画面の設定でJSONバックアップを書き出し、公開版の初期画面から読み込んでください。端末間の自動同期はありません。

`main`へのpushでGitHub Actionsがテスト・ビルドし、GitHub Pagesへ公開します。PagesのSourceはGitHub Actionsです。

### HTMLをダブルクリックして使う

`StudyTrace.html` をChromeまたはEdgeで開いてください。コード・スタイルを1ファイルに含むため、Node.jsやHTTPサーバーの起動は不要です。再生成は `npm run build:html` です。

記録はHTMLファイル内ではなくブラウザのIndexedDBに保存されます。Web版（localhost）とは保存領域が異なるため、既存記録はJSON Export / Importで移してください。同じブラウザ・同じファイルの場所で使い、JSONバックアップを併用してください。HTML版ではService Workerを登録しません。

### ローカルHTTP / PWA版

Node.js 22以上を用意し、このフォルダの `start.cmd` を実行してください。初回のみ依存関係とビルドを用意し、`http://127.0.0.1:5180/` を開きます。ウィンドウを開いたまま使ってください。

```powershell
npm ci
npm test
npm run build
npm run preview -- --port 5180 --strictPort
```

開発時は `npm run dev` を使います。`file://` では利用しません。開発用と本番プレビューでは保存領域が異なるため、日常利用は常に同じURL・ポート・ブラウザに固定してください。

## はじめに

1. 初回設定で教材テンプレートを選択します。すべて外すと空で始められ、JSONバックアップからの再開もできます。
2. 既存の進捗は各授業の「編集」で個別に設定します。旧番号と授業の順番は自動で対応づけません。
3. Sprintを作り、教材ごとに日別・週間・累積完了・具体的タスクの目標を設定します。平日・土日の目標を分けられます。
4. Todayから学習を開始。演習中の「詰まった」と「指導で報告」を残し、終了時にモード固有の結果を保存します。
5. Coachで方針・次回指導・相談事項を記録し、「週間進捗報告」で生成 → 編集 → コピーします。

## 学習方法

| StudyMode | 記録・判定 |
| --- | --- |
| reproduction | 5種の結果、再現度1〜5、複数Attempt。完全独力・再現度5が直近2回、48時間以上離れているとSTABLE。後の失敗で状態は下がります。 |
| speed | 正確性・時間・正誤。正解かつ100%で正の解答時間だけをPB対象とします。初回正答は初回ベスト。 |
| deep_recall | 設定4項目と説明4項目。全8項目の達成率がoverallRecall。solutionRecallは最後まで説明できたかを表します。時間は主要指標にしません。 |
| video | 視聴済み、完了率、理解度、メモ、質問。目標日と開始日があれば登録済み講義数から予定に対する進度を計算します。 |
| past_exam | 大学・年度・科目、時間、得点、満点、大問別得点、失点理由、復習状態。復習は後から履歴で完了にできます。 |
| memorization / reading | 範囲・節、進捗、時間、メモ。 |
| practice | 完了率、結果、難易度。Lectureとの関連を登録できます。 |

完了の意味はモードごとに異なります。数学は再現可能以上、化学は正答100%、物理は全Recall項目、映像は視聴済み100%、過去問は復習済み、暗記・読書・演習は進捗100%です。

### すでに使ったデータの引き継ぎ

1. 旧StudyTraceで「設定 → JSONバックアップを書き出す」。ファイル名を変えて保管してください。
2. 同じブラウザ・同じURLでの更新なら既存データを読み込みます。HTMLの保存場所やブラウザ・ポートを変える場合は、新画面の初期設定または設定でJSONを読み込みます（通常はMerge）。既存データを置き換えるReplaceは内容を確認して使ってください。
3. 「講座・授業 → 対象講座 → 授業一覧の取り込み・既存記録の引き継ぎ」を開きます。
4. 旧「問題53」などを実授業に合わせる場合は、旧項目と実授業を選び、対応を確認して適用します。**元の項目ID、時間、結果、進捗、学習モードを維持**します。章ごとに同じ例題番号があるため、番号だけでの自動対応はしません。
5. 「授業一覧を取り込む」で未登録の授業を追加できます。既存の項目は残ります。不要な旧番号の節は「非表示」で外せます。

講座ごとに「初回変更前」と「直近変更前」の2つを、設定内へバックアップとして保存します。「取り込み前バックアップ」からJSONを書き出して復元できます。これはブラウザ内保存なので、外部へのJSON保存も併用してください。学習済みの重複授業同士は自動統合しません。

### 時間・結果の編集、再計測、削除

- 「学習記録」または各授業の履歴から「時間・結果を編集」。日付、開始時刻、分・秒、8種類の学習結果、メモを修正できます。
- 「再計測」は前回を残して新しい記録を開始します。
- 「削除」は確認後に時間と結果を集計から除外。「削除済みを表示 → 復元」で元に戻せます。
- 記録を変えると、進捗・PB・集計は再計算します。保存済み週間報告の文章は自動変更しません。必要に応じて再生成してください。
- JSONバックアップはschemaVersion 3。旧schemaVersion 1・2も読み込めます。IndexedDBのテーブル構造と既存IDは変更していません。

動画・PDF・問題本文・解説・外部HTML・画像は収録せず、アプリによるスクレイピングも実装していません。「元サイトで開く」で外部URLを別タブに開きます。公開ページにある講義名称と、教材の利用権限は別です。

## 保存・集計ルール

- IndexedDB `StudyTrace` が主データベースです。localStorageは使いません。
- Sessionを開始時に保存し、現在時刻との差分でタイマーを復元します。STOP後は時間が増えず、結果を後から保存できます。閉じていた時間を除く場合は停止後に秒数を修正できます。
- 同時に動かせるタイマーは1つ。DBトランザクションで二重開始を防ぎます。
- 日付をまたぐSessionは、開始時刻のブラウザローカル日付に全時間を計上します。終了していないSessionは確定時間集計から除外し、報告画面で警告します。
- 時間は秒で保持し、文章表示は分単位で丸めます。1日平均の分母は、選んだ期間の全暦日（未学習日も含む）です。
- 今日・週間の項目数は同じ項目への再演習を重複カウントしません。演習回数は別指標です。
- 数学の週間Result件数は各問題の期間内最後の結果を使い、総Attempt数も併記します。
- PBは期間より前の履歴も含めて時系列で判定します。初回ベスト数と更新回数の扱いを文章内に明記します。
- アーカイブは非表示にする操作です。教材・単元・項目の過去記録は保持し、復元できます。
- 単元の「削除」は確認画面を開きます。未学習で関連付けのない単元は中の項目ごと完全削除できます。学習記録・初期進捗・Sprint目標・質問・他項目からの参照がある場合は「記録を残して非表示」を使います。「非表示の教材・単元・項目も表示」をオンにすると復元できます。

## 週間報告

現在のSprint、なければ直近の指導〜次回指導、さらに無ければ直近7日間が初期期間です。開始日・終了日を含めて集計します。

Compact / Detailed、日別時間を含む／合計のみを切り替えられます。「提出文を生成」で決定論的に文章を生成します。自由記述は意味を書き換えません。報告Pinは優先表示し、Compactの件数上限を超えてもPinは省きません。

編集済みの文章は独立したDraftとして自動保存し、元のAttemptやSessionは変更しません。「記録から再生成」は編集を置き換える確認を行います。文章を直接送信する機能はなく、コピーした内容を自分で確認してメッセージアプリへ貼り付けます。

## バックアップ

- JSON：`schemaVersion: 2`, `exportedAt`, 全13テーブル。v1形式（Draftテーブルなし）も受け入れます。
- Import前にZodで型、日付、URL、ID重複、外部キー、モード整合性を検証し、単一トランザクションで反映します。
- Replaceは明示確認後に全データを置き換えます。事前に現在のJSONを書き出してください。
- Mergeは同じID・同じ内容を保持し、新規IDを追加します。同じIDで内容が異なると全取り込みを中止し、既存データを保持します。
- CSV：全StudySessionとAttempt。BOM付きUTF-8、引用符処理と数式注入対策を行います。完全な復元はJSONを使用します。
- 教材だけのImport例は `examples/course-import.json`。これは形式例であり、架空の公式講義ではありません。

ブラウザのデータ削除・プライベートモード・端末故障に備えてJSONを別の場所にも保存してください。Settingsの永続ストレージ要求はブラウザが判断するため、バックアップの代替ではありません。

## DBと構成

`src/db/database.ts` に全スキーマを定義しています。v1は courses / units / studyItems / studySessions / attempts / bottlenecks / sprints / sprintGoals / coachSessions / coachDirectives / coachQuestions / settings。v2で progressReportDrafts を追加します。既存テーブルの再生成や破壊的移行は行いません。

AttemptはStudyModeで判別するZod discriminated unionです。演習中の入力は settings の `runner:<sessionId>` に型検証可能な下書きとして保存し、Bottleneckは予約済みAttempt ID（Session IDと同じ）に紐付けます。完了時にSessionとAttemptを同じトランザクションで保存します。

- `src/domain/`：Mastery・PB・進捗・Sprint・時間・週間文章のpure functions
- `src/studyModes/`：8種類の専用入力画面
- `src/features/`：教材テンプレート／外部カタログ、保存処理、バックアップ
- `src/pages/`：Today、教材、演習、Sprint、分析、Coach、設定
- `src/tests/`：Vitestとfake-indexeddbによる集計・保存・移行・失敗時保全テスト

## GitHub Pages

1. このフォルダをGitリポジトリ `studytrace` として作成し、GitHubにpushします。
2. リポジトリの Settings → Pages → Source を GitHub Actions にします。
3. mainへpushするか、同梱の `Verify and deploy StudyTrace` を手動実行します。

Viteの相対baseとHashRouterを使用するため、`https://<user>.github.io/studytrace/#/courses` などのサブディレクトリと再読み込みに対応します。配信するのは `dist/` の静的ファイルだけです。この作業ではGitHubへの公開・リポジトリ作成は行っていません。

PWAはビルド時にアプリ資産をプリキャッシュします。初回オンライン読込後、アプリ本体をオフラインで利用できます。外部教材はキャッシュしません。更新中に学習を中断させないため、自動でタブを再読み込みしません。

PWAのIDは `/studytrace/` に固定しています。manifestの `id: "./"` はmanifestの場所ではなくオリジン直下の `/` に解決され、同じGitHub Pagesホストの別アプリと衝突します。`studytrace.webmanifest` は通常画面とインストール専用ページで共用し、起動先は同じ保存領域の `index.html?launch=pwa` です。専用ページとそのスクリプトはプリキャッシュ・画面フォールバックの対象から外し、最新のインストール案内を取得します。

## 検証

`npm test` と `npm run build` で確認できます。ビルド後の `npm run verify:pwa` ではPWAのID、起動先、アイコン、専用ページのキャッシュ除外を検証します。GitHub Actionsでもデプロイ前に実行します。実ブラウザ確認の範囲と未確認事項は `VERIFICATION.md` に記録します。
